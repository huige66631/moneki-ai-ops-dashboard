# 第三关状态

## 当前状态

第三关已完成核心实现。第一关提供可复算的看板 API，第二关提供三个白名单查询工具、确定性回答渲染器、可展开的证据区和 Mock/DeepSeek provider；本阶段补齐短期会话、日期替换型追问、独立数字一致性测试和显式看板联动。

当前限制：

- 会话状态仅存于 API 进程内存，重启后丢失；空闲 30 分钟过期，最多 100 个会话。
- 回答保留其原始日期范围；用户点击“查看此范围”后，App 统一加载 dashboard，驱动指标、趋势和 Top 10。
- 后端已建立独立 SQL/窗口计算的数字一致性回归矩阵，并覆盖会话过期、淘汰、追问继承和旧客户端兼容。

## 已确认决策

- 第三关优先实现多轮追问、数字一致性测试和图表日期范围联动。
- 会话状态使用服务端内存和 30 分钟空闲过期，适合当前本地单进程作业演示，不引入数据库消息表。
- 回答中的数字继续由后端确定性渲染，不能交给模型改写。
- 前端只依据后端返回的导航指令切换看板，不能从回答文本猜日期或门店。
- 当前三个第二关意图都只需要日期范围联动。`store_id` 保留为可选导航字段，暂不扩展第一关 dashboard API 的门店筛选。

## 验证结果

- `cd frontend; npm run build`：生产构建成功。
- Impeccable detector：changed frontend targets 无发现。
